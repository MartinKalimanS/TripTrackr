# F14 Accessibility sweep (T560), as built

Branch `feat/f14-a11y` (from `feat/ui-stack`). Task T560 of `tasks.md`; spec FR-070, FR-075, FR-076, FR-077, FR-080; SC-015;
`reference/UI-SPEC.md` (the sections of each screen); `quickstart.md` section 8. Every claim below that a screen reader "says"

or TalkBack: those are the DEVICE checks at the end.

## What was built

- **`test/helpers/a11y-nodes.ts`** (not a test file; `a11y-nodes.test.tsx` pins it): `accessibleNodes()` lists the stops of a screen
  in tree order the way a reader walks them (hidden subtrees skipped; a `Text`, field, switch, labelled image or `accessible` group is
  ONE stop; the name is the label or the text inside, white space normalised), with the id, role, state, hint, value and custom
  actions of each. `expectReadingOrder()` asserts an ordered subsequence of ids, names or patterns (a new element is additive, a moved
  one fails, and the failure prints the whole tree). `unnamed()` finds a control with no name. `exposedArt()` finds a drawing (vector,
  glyph, scrim, cover, stamp art) that nothing hides and nothing speaks for.
- **`test/a11y/order-*.test.tsx`**: one order test per screen: Home (half, peek, full, no trips, unreadable store, loading), the real
  Home sheet handle, Trips, a trip (with and without stops), You, the forms (New trip, the stop editor adding and editing, New
  expense), notes and spending, photos, documents and offline maps, Welcome, Sign in, Create account. Each also asserts no unnamed
  control and no exposed drawing.
- **`test/a11y/reach-all.test.tsx`** over a 30-country fixture (`test/helpers/country-fixture.ts`), **`decorative-art.test.tsx`**,
  **`figures-final-value.test.tsx`**, **`locale-formats.test.tsx`**.

## Deviations and findings (not changed, and why)

1. **Reading order is TREE order.** iOS and Android may also sort by position on the screen, which only a device shows. Two places where
   the tree differs from the picture: the Home sheet's handle is the sheet's LAST child (it is drawn over the content, contract C5-22),
   and a trip's day strip is ONE pinned instance after the scroll view (contract C5-20 already lists "the reading order of the strip" as
   a device-only check). Moving either would change what a reader hears (FR-075) and the stacking; left, as device checks.
2. **Stamps read column by column.** The passport page is two columns and a column is a container: in the tree the stamps read newest,
   third newest... then second, fourth... Pinned as built (the layout and its tests are F13's). Device check: row by row on a device?
3. **A field's label is read twice** in the forms (the kit's visible `Label` text, then the field, named the same: "Email", "Email"). The
   field's name is the parity baseline's and the label is the kit's own text; hiding the label would change what is announced and break
   the text queries of many suites. Owner decision: whether to hide the visible label from assistive technology (the field keeps its name).
4. **The stop editor's "2 nights" value has `role header`**, pre-existing from F6; not changed (FR-075: roles unchanged).
5. **The date formatters of `stop-dates.ts` and `document-ticket.ts` are built once at import with `Intl.DateTimeFormat(undefined, ...)`**
   (the platform default locale, which on Hermes is the device's), not `deviceLocale().languageTag`. They follow the device language at
   launch; a language change while the app is open is not followed. In Jest the default is the machine's (these suites printed Spanish
   month names on the author's machine), so the suites compare against the same helpers. Changing it would change the text of every date
   on a trip and the Maestro flows that read it: an owner decision, not a sweep fix.
6. **`quickstart.md` section 8 says a country row reads "Portugal, 3 trips, first visited 2021"; the built row (F2, the picture wins) reads
   "Portugal, 2 trips, last visited Oct 2026"** ("planned Mar 2027" for a planned-only country). The test pins the built name; the
   quickstart line should be updated by whoever owns it (not edited here).
7. **The Trips tab's Search is a coming-soon button that is last in the tree** (after "Plan a trip"): additive (FR-080).
8. **Welcome has three ways in** (Apple on iOS, Google "coming soon" and disabled, "Continue with email") plus "Sign in", as F12 built it;
   the order test pins that.
